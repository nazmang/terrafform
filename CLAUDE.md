# Terraform: инструкции для агентов

## Модульная архитектура — по максимуму

- Ресурсы живут в `modules/<имя>/`. Корни `infra/<проект>/` только вызывают
  модули и задают значения.
- Новый тип ресурса — сначала модуль, потом вызов из корня.
- Образец модуля: `hetzner_instances`, `proxmox_vm`, `hetzner_storage_box`:
  map объектов + `defaults` (при необходимости `overrides`), `optional()` с
  откатом на defaults, `README.md` с примером.
- Голые ресурсы в старом корне — предложить вынести в модуль, без задачи не
  переписывать.

## Состояние и секреты

- State локальный (`terraform.tfstate` в каталоге корня), `*.tfvars` и state в
  git не входят.
- Токены и пароли в чат и в аргументы команд не выводить. Сгенерированные
  пароли (`random_password`) читать только `terraform output -raw` в пайп,
  не на экран.

## Порядок работы

- `plan -out=<файл>` делает агент, `apply` этого плана запускает админ.
- Коммит — с разрешения админа, пуш — только по его слову.
- Незаконченное git-состояние в `main` (cherry-pick и т. п.) не разрешать
  самому — работать в worktree.
- `phv3.bdinfra.net` (default `pm_api_url` в `infra/proxmox/variables.tf`) не
  трогать; рабочий адрес задаёт `terraform.tfvars`.
